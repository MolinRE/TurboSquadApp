# Сквозная проверка банка Вопросов — #50

Дата: 27.09.2026. Проверка выполнена в браузере на собранных `front`, `api` и PostgreSQL из `docker compose` с отдельным проектом `turbo-issue-50` и чистым томом БД. Адреса фронта: `http://localhost:3000` и `http://127.0.0.1:3000`; API: `http://127.0.0.1:5017`.

## Проход Методиста

1. На `/login` выбрать «Руководитель-методист», без ручного ввода JWT. Открыть `/cms/questions`: видны сидовые Вопросы и справочники.
2. Создать Черновик типа «Один ответ», сохранить неполным и нажать «Сохранить и опубликовать». Ошибки появляются у лимита времени, формулировки, Темы, вариантов, ключевого факта и Источника. Заполнить поля, добавить два варианта с одним верным, указать Категорию и Класс, опубликовать.
3. Исправить формулировку опубликованного Вопроса, сохранить и перезагрузить страницу. Новая формулировка и статус сохраняются. Снять Вопрос с публикации: в списке он становится Черновиком.
4. В том же Черновике последовательно проверить остальные типы: «Несколько ответов» (три варианта, два верных), «Последовательность» (три шага, перестановка шагов), «Свайп» (обе подписи, верная сторона, изменения Шкал). Каждый тип удалось сохранить и опубликовать через браузер и реальный API. Пустые подписи свайпа показывают по одной ошибке у соответствующего поля.
5. Для опубликованного свайпа задать Тему `Проверка CMS`, Категорию `Демо`, Класс `Первый`, Тип `Свайп` и Статус `Опубликованные`: найден ровно тестовый Вопрос. Значения `Нештатная` для Категории, `Стандарт` для Класса, `Черновики` для Статуса и `Последовательность` для Типа по отдельности дают пустую выборку.

## Доступ

- Проводник после демо-входа при прямом открытии `/cms/questions` видит «Для банка Вопросов нужна роль Методиста»; действий редактирования нет.
- По PRD демо-аккаунт «Руководитель-методист» имеет **обе** роли и вправе редактировать. Чтобы проверить чистую роль Руководителя в браузере, в изолированной тестовой БД временно удалили роль `methodologist` у этого аккаунта. После нового демо-входа страница показала тот же отказ и не предложила создать Черновик. Роль сразу восстановили. Backend-тест `Only_methodologist_can_access_question_bank` также проверяет 403 на создание Вопроса для чистой роли Руководителя и Проводника.
- Для проверки истечения JWT в локальном Compose запускали API с временным override `Jwt__ExpirationMinutes: "1"` (файл вне репозитория). После истечения токена и обновления банка браузер перешёл на `/login`. Срок в обычной конфигурации не менялся.

## Найденные и исправленные несовпадения

- API разрешал CORS для `localhost:3000`, но отклонял `127.0.0.1:3000`: демо-вход с этого адреса заканчивался `Failed to fetch`. После добавления origin вход и загрузка банка работают по обоим адресам.
- `id` списка подсказок фильтра Категории совпадал с `id` поля Категорий в редакторе. Подпись поля указывала на список подсказок; после исправления поле снова доступно по подписи.
- До ответа API страница кратко показывала кнопку создания даже пользователю без доступа. Теперь на этом этапе видна только загрузка, затем отказ.
- У пустых подписей свайпа одинаковая ошибка повторялась возле поля и ниже блока. Теперь она показана один раз; подписи сторон изложены по-русски.
