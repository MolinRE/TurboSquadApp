# Условия — структурированные записи трёх типов, объединяемые только по «И»

Условия в графе События задаются не текстовыми формулами и не скриптами, а структурированными записями фиксированных типов: значение Шкалы, наличие Флага, Класс обслуживания (плюс, возможно, «случайность» с записью результата броска в журнал). Условия можно вешать на Вариант, на переход и на само Событие (фильтр пула Рейса); список Условий объединяется только по «И». Так каждый тип — это одно поле формы в CMS, одна схема, которую ИИ стабильно генерирует, и одна проверка валидатора, а жюри видит логику, а не код внутри данных.

## Considered Options

- **Язык выражений** (`loyalty < 40 && (flag.x || class == "Первый")`): отклонено. Нужен парсер, редактор формул и отдельная валидация; ИИ генерирует такие строки с ошибками.
- **Скрипты в контенте (JS/Lua)**: отклонено. Произвольный код в данных нельзя провалидировать и объяснить, это ещё и риск безопасности.

## Consequences

- «ИЛИ» выражается двумя переходами, сравнение Шкал между собой и счётчики («дважды опоздал») недоступны. Прототип на Событиях №6 и №33 (ветка `prototype/trip-engine`) обошёлся тремя типами без «ИЛИ».
- Условие по Классу ссылается на неизменный код класса (`standard`, `comfort`, `business`, `first`), а не на название: справочник Классов редактируется в CMS, и переименование не должно молча ломать Условия.
- Новый тип Условия добавляется одним классом в движке и одним полем в CMS, без переписывания ядра.
