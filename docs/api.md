# Интеграционный API для HR

HR-система или LMS компании забирает из «Турбо-бригады» успеваемость Проводника: Очки компетенций, Звание, Процент успеваемости в целом и по Темам, итоги Рейсов. API только читает данные, JWT для него не нужен, доступ даёт ключ сервиса (PRD v7 §15).

## Ключ сервиса

Каждый запрос передаёт ключ в заголовке `X-Api-Key`. Если заголовка нет, ключ неверный или ключ не задан на сервере, ответ — `401`.

- **Docker Compose** берёт ключ из переменной `INTEGRATION_API_KEY` в `.env` (см. `.env.example`) и передаёт его API как `Integration__ApiKey`. Без переменной подставляется демо-ключ `local_demo_integration_key`, для реальной интеграции его нужно заменить.
- **`dotnet run`** читает ключ из настройки `Integration:ApiKey`: например, переменная окружения `Integration__ApiKey=...` перед запуском.

## Методы

### `GET /api/integration/employees/{externalId}`

Успеваемость одного Проводника. `externalId` — логин Проводника, регистр не важен. Если Проводника с таким логином нет (или это учётная запись Руководителя или Методиста), ответ — `404`.

```bash
curl -H "X-Api-Key: local_demo_integration_key" \
  http://localhost:5017/api/integration/employees/conductor-star
```

```json
{
  "externalId": "conductor-star",
  "displayName": "Марина Соколова",
  "depot": "Северное депо",
  "brigade": "Бригада 1",
  "competencePoints": 140,
  "rank": "Старший проводник",
  "knowledge": { "encountered": 16, "mastered": 14, "successRate": 0.88 },
  "topics": [
    { "topic": "Конфликты", "encountered": 4, "mastered": 3, "successRate": 0.75 },
    { "topic": "Медпомощь", "encountered": 2, "mastered": 2, "successRate": 1 },
    { "topic": "Посадка и документы", "encountered": 7, "mastered": 6, "successRate": 0.86 }
  ],
  "trips": { "finished": 1, "arrived": 1, "failed": 0 },
  "lastActivityAt": "2026-09-27T18:54:25.455211+00:00"
}
```

| Поле | Что значит |
| --- | --- |
| `competencePoints`, `rank` | Очки компетенций и Звание, как в профиле Проводника |
| `knowledge.encountered` / `mastered` | сколько Единиц знания (Вопросов и Шагов Рейса) встречено и сколько из них освоено |
| `successRate` | Процент успеваемости, доля от 0 до 1 с точностью до 0,01; `null`, если ничего не встречено |
| `topics` | то же по Темам: у Вопроса — Тема из банка, у Шага — Тема его События |
| `trips` | завершённые Рейсы: `arrived` — Прибытие, `failed` — Срыв; идущие не считаются |
| `lastActivityAt` | время последней попытки по любой Единице знания; `null`, если попыток не было |

### `GET /api/integration/employees?depot=&brigade=`

Список Проводников в том же формате, но без `topics`. `depot` и `brigade` — названия Депо и Бригады, оба фильтра необязательны; без фильтров возвращаются все Проводники.

```bash
curl -G -H "X-Api-Key: local_demo_integration_key" \
  --data-urlencode "depot=Северное депо" --data-urlencode "brigade=Бригада 1" \
  http://localhost:5017/api/integration/employees
```

## Swagger

Swagger доступен по адресу [http://localhost:5017/swagger](http://localhost:5017/swagger) (в Compose API запускается в Development), методы собраны в группе «Интеграция». Чтобы вызвать метод из Swagger, нажмите **Authorize** и введите ключ в поле `ApiKey`.

## Почему `externalId` — логин

Отдельной колонки для идентификатора сотрудника во внешней системе в схеме нет. Добавить её — значит сделать миграцию общей базы и завести сопоставление, а без импорта сотрудников сопоставлять не с чем. Поэтому идентификатором служит уникальный логин Проводника: при заведении учётных записей HR задаёт логин равным табельному номеру или логину в своей системе.
